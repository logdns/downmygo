# 参考：MDM 分析与功能对照

> 这份文档记录 downmygo 立项时对 **Mister Download Manager（MDM）** 的拆解，以及今天的功能对照。它是参考，不是规格：downmygo 是独立实现，不含 MDM 的代码、图标或文案。

## 1. 为什么看 MDM

MDM 是一个 Windows 上的商业下载器，功能覆盖很全（浏览器接管、站点登录、队列、调度、限速、种子、视频、图库、解压、debrid、i18n）。它的**工作流**值得学，**实现方式**不必学：

| 方面 | MDM 的做法 | downmygo 的选择 |
|---|---|---|
| 界面 | 传统 Win32 控件，信息密度高 | 原生 GPU 绘制，留白更多，三种语言 |
| 浏览器接管 | 自研扩展 + 本机协议 | 标准 Native Messaging + MV3 扩展 |
| 引擎 | 多连接 + 分段 | 同样，但分段动态二分、stall 看门狗 |
| 站点 | 内置解析器 | 交给 yt-dlp / gallery-dl，自动安装 |
| 种子 | 内置 | 内置（anacrolix/torrent） |
| 配置 | 注册表 | 一个 `state.json`，可读可备份 |
| 平台 | 仅 Windows | macOS / Windows / Linux |

## 3. 从 MDM 学到的东西

1. **浏览器接管是下载器的入口**：没有它，用户要复制粘贴两次。所以扩展、深链、剪贴板三条路都做。
2. **队列和调度比速度更影响体验**：半夜限速、完成后关机，是真实需求。
3. **站点适配不能靠自研**：站点天天变，交给 yt-dlp / gallery-dl 这类社区工具，自己负责安装与进度。
4. **种子是下载器的一部分**：用户不想要两个应用。内置客户端 + 做种控制是必要的。
5. **更新要能自己完成**：否则用户永远停在旧版本。
6. **配置要能被用户看见**：一个可读的 `state.json` 比注册表好排查。

## 4. 明确不学的地方

- 信息密度：MDM 一屏塞几十个控件；downmygo 用留白和分组。
- 视觉：不复刻 MDM 的图标、配色、文案。
- 商业模式：没有广告位、没有「加速」付费墙。
