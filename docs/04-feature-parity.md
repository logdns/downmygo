> 状态说明：

## 1. 核心下载

| MDM 功能 | downmygo | 说明 |

| 崩溃/重启后续传 | ✅ | 原子状态，最多丢 2 秒 |
| 服务器不支持 Range 时单流 | ✅ | 自动回退，UI 标注 |
| 重定向 | ✅ | 最多 10 次 |
| 文件名解析 | ✅ | Content-Disposition / RFC 5987 / URL |
| 文件名安全化 | ✅ | Windows 保留名、控制字符、长度 |
| 重复链接策略 | ◐ | 询问/编号/覆盖/复用逻辑已有；UI 提示较简 |
| 文件已存在自动编号 | ✅ | 绝不覆盖非自己创建的文件 |
| SHA-256 校验 | ✅ | 添加框高级选项 / CLI `--checksum` |

| FTP/FTPS | ○ | 引擎接口预留，未实现 |

| 网络适配器绑定 / kill switch | ◐ | 引擎支持 `BindIP`；无网卡选择 UI |

## 9. 明确不做

| 功能 | 原因 |
|---|---|
| 账号/云同步 | 与“本地、隐私、无账号”定位冲突 |
| 广告/推荐/捆绑 | 品牌原则 |
| 破解/绕过付费服务 | 法律与道德 |
| 内置浏览器 | 用系统浏览器 + 扩展 |
| 移动端原生 App | 远程页面足够；原生 App 成本高 |
| 复刻 IDM 视觉 | 只保留工作流，视觉独立 |

---

## 10. 结论

v1.0 已经把**下载器最核心的 60%** 做扎实：引擎、续传、列表、分类、队列、调度、限速、设置、托盘、CLI、API、远程页面、主题、测试。

剩余 40% 是“生态型能力”：浏览器扩展、种子、视频、图库、解压、debrid、DNS/VPN、MCP、i18n、更新。这些按 v1.1–v1.3 推进，不影响 v1.0 作为日常下载器的可用性。
